# v0.4 验收记录

本轮在 M1／8 GB、1440×960桌面工作区及540×768窄屏上实际操作。项目使用真实Bellinge地貌和洪涝业务；验收的是参考视频可见流程的对应与数据一致性，不是同一地形的像素复制。

## 功能与数据

- 26个参考片段在两个情景各运行一次，共52次逐段检查并截图；详见[片段对照](VIDEO-PARITY.md)。
- 六机选择、相机可见光 / 水深 / 风险、伪彩 / 灰阶、云台、变焦、全屏及还原；模式切换保持姿态与物理时间。
- 十三个资源选择、随行、装载 / 投送 / 返程 / 补给；2 m间距独立导航采样、物资守恒及倒拖恢复。
- 五个工作空间的25种直接切换组合；另检查补给站直接切无人机，防止旧面板更新跨对象类型出错。
- 完整115秒自动导览实际播放，片段内对象持续移动，结束后停止推进。
- 暂停前后完整水场的FNV校验、人物实例矩阵、资源姿态、库存、人员及累计量一致；视觉水纹 / 雨滴继续。
- 实际下载两情景快照，核查模型ID、站点、行动、相机、坐标原点和单位。
- 历史雨峰108 mm/h时绘制487条雨线，透明度约0.297；窗口末rg5425累计19.40046 mm，P04展示水深约1.210 m。水深为模型结果。
- 初始数据失败时禁用尚不可用操作，保留重试；情景切换失败保留当前结果，解除故障后可重试。
- 窄屏无横向溢出；相机自动滚入视野，云台底部约487 px，在500 px地图区域内完整可见。

精简记录：`validation/v4/browser-checks.json`、`mission-checks.json`、`navigation-checks.json`。完整截图、实际下载与原始运行记录保留在SSD的同名验收目录。参考原视频不随仓库分发。

## 本轮发现并修复

1. 新增缓存与图标名称冲突，导致首屏初始化失败；改正图标别名。
2. 侦察窗口被主地图标签、控件穿透；调整浮层与遮挡处理。
3. 深水任务指向偏干或计算域边界；改为从各情景实际水场挑选内部湿区目标，补充明确的自动色标。
4. 从资源直接切到无人机时，旧面板读取新对象的非对应字段；调整切换顺序并对指标类型作检查，补测全部工作空间组合。
5. 切换选中对象后，任务路径可能保留旧可见状态；把选中对象与图层变化加入刷新条件。
6. 窄屏相机云台被裁切、从下方详情打开后窗口不在视野；调整位置、遮挡和滚动定位。
7. 初始加载尚未成功就可点击场景操作；添加禁用与重试状态。

## 性能与持续运行

结果见 `validation/v4/performance-checks.json`。帧率取实际requestAnimationFrame区间的中位数；不作为所有设备、浏览器或分辨率的保证。堆内存为浏览器JavaScript读数，不等同于操作系统或GPU总内存。

长时检查覆盖渲染、水场、人员与行动核心；末次窄屏位置和打开滚动修复在最终构建另行检查，未改动计算、行动采样或渲染核心。记录保留对应构建标识和原始样本，不把不同检查的范围混为一项。


量化结果：浏览器检查105项，物资6项、导航6项；主景与画中画中位约59.9 FPS，播放车辆时也约59.9 FPS。核心连续运行31.19分钟、106,790帧，未捕获异常0、上下文丢失0。五轮切换预热后堆变化约0.28%，几何348、纹理6，活跃水场1。
